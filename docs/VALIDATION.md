«صفحه رندر می‌شود» اعتبارسنجی نیست. سه لایه اعتبارسنجی مستقل انجام شده است.

## 1. تست‌های صحت متریک (fixture قطعی)

`tests/` — دیتاست مصنوعی کوچکی که همه حالت‌های خطرناک را پوشش می‌دهد
(`tests/conftest.py`)، و ۵۱ تست (صحت متریک + API + هوش مصنوعی + مرکز کنترل + منابع داده) که اشتباهات مرگبار را قفل می‌کنند:

- تلاش‌ها هرگز به‌جای جلسه شمرده نمی‌شوند (۹ ردیف تلاش → ۸ جلسه)
- تلاش مجدد GMV و تعداد تراکنش را چندبرابر نمی‌کند
- NoAttempt خطای بانکی حساب نمی‌شود
- Paid موفقیت حساب نمی‌شود؛ مبلغ آن جدا گزارش می‌شود
- «موفقیت اولین تلاش» هرگز از تبدیل نهایی بیشتر نمی‌شود (تعریف Verified-پایه)
- محاسبه مشتری تکراری merchant-scoped است (کارت‌های دو پذیرنده هرگز ادغام نمی‌شوند)
- تجزیه LMDI دقیقاً جمع می‌شود؛ تجزیه Δتبدیل نیز هویت جبری دارد
- با استخر همتای کوچک، هیچ صدکی جعل نمی‌شود (سرکوب کامل)
- فرصت = فرمول شکاف، نه جمع مبالغ ناموفق (تست ساختاری فرمول)
- شکاف کمتر از 2pp کارت نمی‌سازد
- برچسب adjusted_fee همیشه «شاخص نسبی» است

آخرین اجرا: **51 passed** (`uv run pytest -q`).

### تست‌های سطح پلتفرم (فاز دوسطحی)
- سیاست فقط-رایگان: مدل غیررایگان و `openrouter/auto` رد می‌شوند؛ پیش‌فرض رایگان است.
- لایهٔ زمینهٔ ایمن: هرگز ردیف خام/کارت/SQL/پارامتر/راز به مدل نمی‌رسد (اسکن `assert_safe`).
- گراندینگ: مدل زبانی نمی‌تواند عددی بسازد که موتور قطعی نساخته باشد → بازگشت به پاسخ قطعی.
- fallback هنگام خطای ارائه‌دهنده و حالت آفلاین (بدون کلید).
- تله‌متری هوش مصنوعی و ردیابی هزینه ثبت می‌شوند؛ API مرکز کنترل پاسخ می‌دهد.
- GA4 بدون پیکربندی وضعیت صادقانه دارد؛ کلیدهای ناامن از متریک منبع حذف می‌شوند.
- کوپایلوت عملیات مستند است و merchant را لو نمی‌دهد.
