# سناریوی ویدئوی دمو (۵–۸ دقیقه) | DEMO SCRIPT

ضبط: دسکتاپ (۱۴۴۰px) + موبایل (نمای ریسپانسیو مرورگر 390×844 یا گوشی واقعی).
پیش از ضبط: `uv run zarin` → http://localhost:8630 . همه اعداد زنده از داده محاسبه می‌شوند.

## چک‌لیست چیزهایی که باید روی صفحه دیده شوند

- [ ] اجرای تک‌فرمان `uv run zarin` در ترمینال (چند ثانیه)
- [ ] فید فرصت‌ها با رتبه و بازه ریالی (دسکتاپ)
- [ ] کشوی «این عدد از کجا آمد؟» تا سطح SQL و session_key
- [ ] قیف با ۵ حالت نتیجه + اولین‌تلاش/نهایی + نجات
- [ ] پرداخت‌های تاییدنشده (M156)
- [ ] یکپارچه‌سازی خراب (M265)
- [ ] نجات با تلاش مجدد (M43)
- [ ] مشتریان: کوهورت + تکرار + غیرفعال‌های ارزشمند
- [ ] همتایان: «چرا این همتایان؟» + صدک + یک مورد سرکوب‌شده
- [ ] چه چیزی تغییر کرد: آبشار LMDI + ریشه تغییر تبدیل
- [ ] بپرس: دو پرسش + شواهد پاسخ
- [ ] کیفیت داده
- [ ] **تمام مسیر بالا یک بار هم روی موبایل** (الزام چالش)
- [ ] `uv run pytest -q` و `uv run python pipeline/validate.py` (چند ثانیه، برای اعتماد داور)

## سناریو

**۰:۰۰ – افتتاح (۳۰ث).** «پذیرنده زرین‌پال هزاران تراکنش دارد اما یک سوال: این هفته چه کنم؟
زرین‌بین داده پرداخت را به تصمیم تبدیل می‌کند — و برای هر عدد، تا خود داده خام سند می‌دهد.»
ترمینال: `uv run zarin` → مرورگر.

**۰:۳۰ – فید اقدام (۱د).** پذیرنده M156 (پیش‌فرض). نوار KPI را بخوانید. روی فرصت ۱ مکث کنید:
ساختار مشاهده/تشخیص/اقدام/اطمینان را نشان دهید. جمله کلیدی: «به‌جای ۴۷ نمودار، سه کار مهم.»

**۱:۳۰ – ردیابی (۱د).** روی «این عدد از کجا آمد؟» کلیک کنید. تعریف، فرمول، SQL واقعی،
پارامترها، حجم نمونه؛ سپس «نمایش نمونه جلسه‌های منبع» و session_key ها.
جمله کلیدی: «این SQL نمایشی نیست؛ همان کوئری‌ای است که همین الان اجرا شد.»

**۲:۳۰ – بینش بدیع: پول رسیده ولی تایید نشده (۴۵ث).** بنر زرد M156: ‏۹۱۲ پرداخت / ۶۱٫۸ میلیارد
ریال تسویه‌شده بدون Verify. اقدام: اصلاح کال‌بک/تایید خودکار. «این برآورد نیست؛ پول واقعی است.»

**۳:۱۵ – قیف و نجات پرداخت (۱د).** صفحه قیف M43: پنج حالت جدا (تاکید: NoAttempt ≠ خطای
بانکی). اولین‌تلاش در برابر نهایی؛ ۹,۷۴۵ جلسه نجات‌یافته. باندهای مبلغ درون-پذیرنده و جدول PSP.

**۴:۱۵ – کشف خرابی (۳۰ث).** سوییچ به M265 از پیشنهادهای دمو: تبدیل ۱٫۷٪، انصراف ۹۴٪،
کارت «انصراف بالاتر از همتایان» با شکاف ۸۸ واحد درصد. «زرین‌بین بدون هیچ تنظیم دستی این
پذیرنده را پیدا کرد.»

**۴:۴۵ – مشتریان (۴۵ث).** M156: سهم تکرار، کوهورت ماهانه، تمرکز ۵ مشتری، غیرفعال‌های ارزشمند.
یادآوری صادقانه: «فقط پرداخت‌کنندگان موفق دیده می‌شوند — و محصول همین را می‌گوید.»

**۵:۳۰ – همتایان + چه‌چیزی‌تغییرکرد (۱د).** «چرا این همتایان؟» و صدک‌ها؛ یک متریک سرکوب‌شده
را نشان دهید («عدد جعل نمی‌کنیم»). سپس آبشار LMDI و ریشه تغییر تبدیل.

**۶:۳۰ – بپرس (۳۰ث).** «این هفته روی چه تمرکز کنم؟» و «تلاش مجدد چقدر برگرداند؟» + دکمه
شواهد پاسخ. «بدون LLM — قطعی، آفلاین، ردیابی‌پذیر.»

**۷:۰۰ – موبایل (۱د).** DevTools → 390×844 (یا گوشی). همان مسیر: فید، کشوی شواهد، قیف،
بپرس، ناوبری پایین. «همه قابلیت‌ها روی موبایل.»

**۸:۰۰ – بستن (۳۰ث).** `uv run pytest -q` (۲۳ پاس) و `pipeline/validate.py` (24/24).
«زرین‌بین: عدد مشخص، اقدام مشخص، سند مشخص — چیزی که یک پذیرنده واقعی هر هفته باز می‌کند.»
